<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sitio auditado -> crawler | `response.headers` y `set-cookie` provienen de sitios arbitrarios no confiables; sus keys y valores son controlados por terceros. |
| crawler -> Postgres (Page) | Los datos capturados se persisten; deben limitarse a headers del allowlist y nombres de cookie (nunca valores/secretos). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-01 | Information Disclosure | `parseCookieNames` / `Page.cookieNames` | high | mitigate | Persistir SOLO nombres de cookie (split antes del primer `=`). Nunca guardar valores/expiry/domain/flags — evita almacenar tokens de sesion de sitios auditados (FPRINT-01). Test dedicado lo verifica. |
| T-25-02 | Tampering | `curateHeaders` (keys de header controladas por el sitio) | medium | mitigate | Iterar sobre el allowlist fijo `CURATED_HEADER_KEYS`, nunca sobre las keys del objeto entrante — un header malicioso `__proto__`/`constructor` nunca se lee ni se asigna como key (previene prototype pollution). |
| T-25-03 | Information Disclosure | `Page.responseHeaders` | medium | mitigate | Persistir solo headers curados (allowlist), no el objeto crudo completo — evita guardar headers sensibles no relacionados con fingerprinting (auth, set-cookie con valor, etc.). |
| T-25-SC | Tampering | instalaciones npm | low | accept | No se instalan paquetes externos nuevos (RESEARCH `## Package Legitimacy Audit`: none). El parseo de cookie usa split nativo, no `set-cookie-parser`. No aplica checkpoint de legitimidad. |
</threat_model>
