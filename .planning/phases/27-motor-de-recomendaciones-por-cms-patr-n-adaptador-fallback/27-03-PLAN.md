<objective>
Cablear el motor `resolveCmsRecommendation` en el único punto de integración (`toReportIssue` de `packages/report-model/src/build.ts`), pasando el `rawStack` crudo y guardando por severidad `ok`. Extender `build.test.ts` con los casos de integración (guard de severidad, check fuera de los 10 intacto, personalización WordPress, stack null) y crear el script e2e `verify-cms-fix.mts` para verificar contra un audit real. Este plan cierra CMSFIX-05 (resolución en report-model, no persistida, gratis en exports) y refuerza CMSFIX-04 en el punto de integración.

Purpose: `ReportModel` es la única fuente de verdad para el reporte web y para las exportaciones (patrón v1.2). Resolver aquí una sola vez hace que la personalización llegue a PDF/Markdown/PPTX sin tocar `packages/export`. El guard de severidad `ok` evita mostrar un "fix" sobre un check que está correcto (regresión de credibilidad).
Output: `build.ts` integrado; tests de integración verdes; script e2e listo.
</objective>
