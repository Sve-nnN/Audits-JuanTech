# Phase 10 — UI Design Contract

> Visual and interaction contract for the full screen assembly: all six auditor screens composed from the Phase 9 component library on top of the Phase 8 tokens/fonts, with subtle motion, humanized Spanish-neutral copy (no voceo), and end-to-end responsive + a11y. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase ships NO new tokens and NO new component primitives. It composes existing pieces (`apps/web/app/components/ui/`) into screens, tokenizes the leftover inline/SVG hex (closes DS-01), adds CSS + WAAPI motion (no framer-motion), and finalizes all copy. Everything references the Phase 8 contract (`08-UI-SPEC.md`, `tokens.css`) and Phase 9 contract (`09-UI-SPEC.md`) as source of truth. Where a component genuinely lacks a needed variant, it is noted as an EXTENSION (never a new primitive).
>
> **Plan mapping (planner):** 8 plans — one per screen (SCREEN-01 home, SCREEN-02 verify, SCREEN-03 progress, SCREEN-04 report, SCREEN-05 pages+graph, SCREEN-06 history) + one cross-cutting motion plan (MOTION-01/02/03, global primitives) + one a11y/responsive sweep (A11Y-01/02/03). Copy (COPY-01/02/03) lands inside each screen plan, sourced from the Copywriting Contract below.

## Global Motion Primitives (MOTION-01/02/03)

All motion is CSS + WAAPI, no libraries, CSP-safe. Every primitive has a hard `prefers-reduced-motion: reduce` branch that jumps to the final state with no animation. Shared timing tokens (add to `tokens.css` as motion tokens — these are DURATIONS not colors, still "tokens" per DS-01 spirit):

| Motion token | Value | Purpose |
|--------------|-------|---------|
| `--motion-fast` | 150ms | Hover/focus micro-interactions (already in Phase 9) |
| `--motion-base` | 300ms | State/opacity transitions |
| `--motion-reveal` | 500ms | Section reveal fade+slide |
| `--motion-count` | 900ms | Score count-up + gauge arc fill |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | Decelerate — reveals, gauge |
| `--ease-standard` | `cubic-bezier(0.4, 0, 0.2, 1)` | General transitions |

### 1. `useCountUp` hook (score count-up + gauge arc) — MOTION-01

- New client hook `apps/web/app/components/motion/useCountUp.ts`. Signature: `useCountUp(target: number, { duration = 900, enabled }: opts): number`.
- Drives BOTH the numeric readout (React state, rAF-stepped, `Math.round`, ease-out) AND the gauge arc via the `--gauge-offset` custom prop already exposed by ScoreGauge (Phase 9 shipped it with no transition — now animated).
- Arc animation: WAAPI `element.animate([{ '--gauge-offset': circumference }, { '--gauge-offset': finalOffset }], { duration: 900, easing: 'cubic-bezier(0.22,1,0.36,1)', fill: 'forwards' })` — or a CSS `transition` on `--gauge-offset` registered via `@property --gauge-offset { syntax:'<number>'; inherits:false; initial-value:0 }` so it is animatable. Number counts 0 → target over the same 900ms.
- Trigger: fires once when the gauge enters the viewport (shares the IntersectionObserver below), not on mount, so above-the-fold and lazy gauges behave the same.
- **Reduced motion:** hook returns `target` immediately, gauge renders at final `--gauge-offset` with no WAAPI animation. No count, no arc sweep.

### 2. `useReveal` / IntersectionObserver section reveal — MOTION-01

- New client hook `apps/web/app/components/motion/useReveal.ts` (or a `<Reveal>` wrapper). Adds a `data-reveal` element to an `IntersectionObserver` (`threshold: 0.15`, `rootMargin: '0px 0px -10% 0px'`, unobserve after first intersect — reveal once).
- CSS: initial state `opacity:0; transform:translateY(16px)`; revealed state (`[data-reveal="in"]`) `opacity:1; transform:none; transition: opacity var(--motion-reveal) var(--ease-out), transform var(--motion-reveal) var(--ease-out)`.
- Stagger: sibling sections use a `--reveal-delay` custom prop stepped 0/60/120/180ms via `transition-delay`. Cap stagger at ~4 steps so nothing feels slow.
- Applies to: report sections (score hero, category grid, diff, issues table, perf, detail accordion), history results, pages list.
- **Reduced motion:** observer still runs but the CSS reveal collapses to the final state instantly (`transition:none; opacity:1; transform:none`). Content is ALWAYS in the DOM (no JS gating of content) so it is present for AT and no-JS.

### 3. Live progress phase bar — MOTION-02

- Reuse the EXISTING polling in `AuditProgress.tsx` (locked — do not rewrite the poll). Add a visual phase indicator on top.
- Three ordered phases: `crawling` → `analyzing` → `performance`. Render a horizontal 3-segment stepper/bar. Current phase segment: `--accent` fill; completed segments: `--success`; pending: `--border`.
- Within `crawling` (the only phase with a real ratio `crawled/total`), the current segment fills proportionally via a `width` transition (`transition: width var(--motion-base) var(--ease-standard)`). `analyzing`/`performance` have no ratio → the active segment shows an indeterminate shimmer (reuse the Skeleton shimmer keyframes) to signal "working, not hung".
- Phase label (Geist Sans 14/600) + sub-caption (14/400 `--text-secondary`) update per poll. A `role="status" aria-live="polite"` region announces phase changes to AT (e.g. "Analizando checks").
- On terminal `failed`: bar turns `--critical`, error copy shown (see copy). On `done`: existing `window.location.reload()` behavior is kept.
- **Reduced motion:** width transition and shimmer are disabled; the bar updates its filled state instantly per poll; the numeric `crawled/total` and phase label still convey progress. No spinner animation.

### 4. Micro-interactions (hover/focus/chevron) — MOTION-01

- Inherited from Phase 9 (≤150ms color transitions, chevron rotate). Accordion chevron rotate 200ms `--ease-standard`. All already guarded; the a11y sweep verifies the guard exists on every one.

**Global reduced-motion contract:** a single `@media (prefers-reduced-motion: reduce)` block in `globals.css` sets `*, *::before, *::after { animation-duration: 0.001ms !important; animation-iteration-count: 1 !important; transition-duration: 0.001ms !important; scroll-behavior: auto !important; }` as a safety net, PLUS each primitive's explicit branch. No motion may play against the preference.

## Accessibility + Responsive Acceptance Bar (A11Y-01/02/03)

The a11y/responsive sweep plan validates every screen against this bar. All must be TRUE:

- **Responsive (A11Y-01):** no horizontal overflow at 360px / 768px / 1280px on any screen. IssuesTable + history table + entity graph scroll/scale within their region, never the page. Every container ≤ viewport. Images/SVG `max-width:100%`.
- **Contrast (A11Y-02):** meaningful text ≥ 4.5:1, large numerals/headings ≥ 3:1, in BOTH themes. Body/caption text uses `--text`/`--text-secondary`, never `--text-muted` (direct fix for UI-FEEDBACK.md low-contrast note — verified with a contrast check on the home subtitle/footnote and report meta lines).
- **Focus (A11Y-02):** every focusable element shows `outline:2px solid var(--ring)` (+`--shadow-focus`) on `focus-visible`; no `outline:none` without replacement. Focus order is logical top→bottom; step machines move focus to the new content.
- **ARIA/semantics (A11Y-02):** native elements first (`<button>`,`<a>`,`<table>`,`<details>`,`<form>`,`<label>`). ScoreGauge/EntityGraph `role="img"`+`aria-label`. Live regions: progress `role="status" aria-live="polite"` + `role="progressbar"`, errors `role="alert"`, empty/loading `role="status"`. Color never the sole signal (severity/status/diff always paired with a word or number).
- **Keyboard (A11Y-03):** accordions (native `<details>`, Enter/Space), theme toggle (Enter/Space, Phase 8), all forms (tab + submit), table scroll regions (`tabindex=0`+`role=region`), and all links/buttons are operable with no keyboard trap. Skip-to-content is a plus (recommended on the report page).
- **Motion (MOTION-03):** every animation/transition (count-up, gauge arc, reveals, phase bar, chevron, hover, success scale) has a `prefers-reduced-motion: reduce` branch that renders the final state with no motion. Verified per primitive AND via the global safety-net media block.
- **Validation process (10-CONTEXT.md):** Claude runs the dev server and captures each screen (dark + light, mobile + desktop) to verify render BEFORE Juan's pixel-perfect final pass. No screen closes without Juan's visual sign-off.
