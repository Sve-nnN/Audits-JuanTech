<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navegador → GET /api/audits/[id]/export | auditId en la URL, free tier sin auth (aceptado en Phase 13); el cliente solo consume el binario |
| Content-Disposition header → nombre de archivo en el cliente | valor de red usado como `download` attr del enlace |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | filename parseado de Content-Disposition | mitigate | Usar el valor solo como `anchor.download` (nunca innerHTML/DOM sink); fallback local `auditoria-<domain|id>.<ext>` si el header falta o no matchea; filename ya sanitizado en Phase 13 |
| T-14-02 | DoS | fetch de export (generación pesada PDF/PPTX) | mitigate | Guard `if (loading) return;` + Button disabled durante loading impiden el doble/multi envío desde un mismo cliente (SC#3) |
| T-14-03 | Info Disclosure | mensaje de error inline | accept | Texto neutro fijo, sin exponer status/stack/detalle técnico al usuario |
| T-14-04 | Resource leak | Object URL del blob | mitigate | `URL.revokeObjectURL` en finally tras el click del enlace temporal |
| T-14-SC | Tampering | devDeps de test (@testing-library/*, jsdom) | mitigate | Solo devDependencies del stack RTL canónico y de registro conocido; no tocan runtime de producción ni el bundle de Vercel |
</threat_model>
