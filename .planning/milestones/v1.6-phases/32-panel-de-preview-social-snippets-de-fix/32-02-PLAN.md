<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cliente (`?url=`) → `route.ts` → red pública/privada del sitio auditado | Entrada controlada por quien renderiza la página del reporte (no anónima de internet, pero SÍ puede apuntar a cualquier URL — el allowlist de origen es la primera defensa) |
| `route.ts` → respuesta del origen auditado → cliente (`<img>`) | El origen auditado es hostil por defecto: controla status, headers y bytes de la respuesta |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-32-05 | Tampering / Elevation of Privilege | `route.ts` — SSRF vía `?url=` apuntando a `169.254.169.254`, `127.0.0.1`, red interna de Railway | high | mitigate | Defensa en dos capas: (1) allowlist de origin EXACTO contra `audit.resolvedUrl` antes de cualquier I/O; (2) `assertPublicDestination` + `pinnedDispatcher` reusados de Phase 31 (resolución DNS + clasificación de IP + pinning anti-rebinding), revalidados en cada salto de redirect vía `resolveRedirect`. Nunca `redirect: "follow"`. |
| T-32-06 | Tampering | DNS rebinding entre la validación de origen y el `fetch` real | high | mitigate | `pinnedDispatcher(addresses)` conecta contra las direcciones ya clasificadas, nunca resuelve el nombre una segunda vez — mismo mecanismo que `imageProbe.ts` (Phase 31). |
| T-32-07 | Tampering / Information Disclosure | Content-type sniffing — el origen sirve un tipo distinto al declarado (p. ej. HTML disfrazado de imagen) | medium | mitigate | `Content-Type` de la respuesta SIEMPRE re-derivado y forzado a un allowlist cerrado de 5 tipos de imagen; nunca se reenvía el header crudo del origen; `X-Content-Type-Options: nosniff` en la respuesta. |
| T-32-08 | Denial of Service | Imagen que gotea bytes indefinidamente o excede el peso razonable | medium | mitigate | `readUpTo(res, OG_IMAGE_MAX_BYTES)` cancela el reader activamente al alcanzar el cap (5 MiB, mismo umbral que IMG-04); el `AbortController`/timeout de `IMAGE_PROBE_TIMEOUT_MS` cubre también la lectura del cuerpo, no solo la conexión. |
| T-32-09 | Information Disclosure | Filtración de detalle técnico (status HTTP real, motivo SSRF, URL interna) en la respuesta del proxy | medium | mitigate | Todas las ramas de error devuelven status genérico (400/403/404) con cuerpo vacío; ningún header ni cuerpo expone `verdict.reason`, el status HTTP real del origen, ni la URL interna rechazada. `PreviewImage.tsx` tampoco muestra código HTTP crudo al usuario (copy fija "No se pudo cargar la imagen."). |
| T-32-10 | Tampering | `PreviewImage.tsx` — inyección de query string hacia la propia ruta vía `ogImage` sin codificar | low | mitigate | `encodeURIComponent(ogImage)` al construir el `src` del `<img>`. |
