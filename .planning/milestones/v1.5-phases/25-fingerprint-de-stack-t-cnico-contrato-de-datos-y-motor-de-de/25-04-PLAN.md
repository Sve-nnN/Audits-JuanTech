<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PageFingerprintInput (HTML/headers/cookies del sitio) -> detectStack | `detectStack` procesa HTML/headers de sitios arbitrarios no confiables; es el mayor foco de superficie DoS de la fase. |
| headers del sitio -> mapa agregado de headers | Las keys de header provienen del sitio; usarlas como keys de objeto sin cuidado abre prototype pollution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-07 | Denial of Service | `aggregate()` / matching sobre HTML adversario | high | mitigate | Truncar cada HTML a `MAX_HTML_BYTES` (~256KB) antes de `cheerio.load`; matchear con selectores cheerio e `includes()`, sin regex de backtracking. |
| T-25-08 | Denial of Service | consumo de memoria por HTML gigante | high | mitigate | No concatenar todo el set en un solo string; elegir una sola pagina para cheerio y truncar por pagina en `aggregate()`. |
| T-25-09 | Tampering | mapa agregado de headers (keys controladas por el sitio) | medium | mitigate | Construir el mapa de headers agregado sin heredar prototipo (objeto sin proto) y escribir solo keys conocidas/lowercased; nunca asignar keys arbitrarias del sitio como propiedades. |
| T-25-10 | Information Disclosure | `evidence`/`value` en Signal/AxisResult (consumido por UI de Phase 26) | low | mitigate | `evidence`/`value` son strings controlados por el motor (ids de firma + nombre de tecnologia), no reflejan valores crudos del sitio. Nombres de cookie SI vienen del sitio: anotar para Phase 26 que la UI debe escaparlos (XSS diferido a 26). |
| T-25-SC | Tampering | instalaciones npm | low | accept | No se instalan paquetes externos nuevos (RESEARCH `## Package Legitimacy Audit`: none). |
</threat_model>
